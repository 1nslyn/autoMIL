In the job launch block (~L899-910), after `cmd = shlex.split(self.run_command)` (or the `cmd = [sys.executable, self.run_script]` branch), add override-append logic:

```
override_str = spec.get("run_command_override")
if override_str:
    cmd = cmd + shlex.split(override_str)
```

CRITICAL security note (per threat model T-11-03-01): this MUST be list append (`cmd + shlex.split(...)`), not string concatenation, and subprocess.Popen MUST NOT use `shell=True`. The existing call already uses `shell=False` (no `shell=True` keyword). `shlex.split` tokenizes the override string safely so shell metacharacters in the override value (`;`, `|`, `&`, etc.) are treated as literal argument tokens, not shell operators. This prevents command-injection even from a maliciously crafted override string.

Do NOT change `start_new_session=True`, `cwd`, `env`, or any other Popen kwargs.
